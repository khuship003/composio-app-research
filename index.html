03

The agent — what actually did the research

Built for real use with Composio's own SDK; run for this submission by Claude directly inside the working session — explained honestly below.
01 · SEED

100-app list

data/apps_seed.json — id, name, category, hint per app, exactly as given in the brief.

02 · RESEARCH

Research agent, pass 1

Per app: 4 targeted queries (docs, auth, self-serve/pricing, MCP) → fetch top pages → Claude extracts the schema, citation required for every non-obvious field.

03 · CRITIC

Independent verification

A separately-prompted, skeptical pass re-derives auth / self-serve / MCP / verdict from fresh sources, never shown pass 1's answer.

04 · HUMAN

Spot-check + correction

Disagreements and low-confidence apps get a human glance at the actual doc page; corrections applied as pass 2, reason logged.

05 · REPORT

Patterns + this page

src/report.py aggregates the corrected dataset into the stats this page is built from.

What's genuinely built and runnable

  • Full pipeline architecture — src/research_agent.py, src/verify_agent.py, src/pipeline.py, src/report.py — all use the real Anthropic SDK and are written against Composio's SDK pattern for the search/scrape toolkit (see src/search_provider.py). Point it at a Composio API key + toolkit and it runs unmodified.
  • A strict schema contract (src/schema.py) every stage shares — no translation layer between what the research agent produces, what the critic checks, and what this page renders.
  • A resumable run — pass 1 results are cached, so a crash on app 60 of 100 doesn't mean starting over.

Where a human — or in this case, a live search — was actually needed

  • The build sandbox for this submission has no outbound network access and no Composio/Anthropic API keys wired in, so python -m src.pipeline could not literally be executed here end-to-end. Instead, the same two-pass shape was run manually: pass 1 came from training knowledge only, then a sample was independently re-checked with live web_search / web_fetch — functionally the critic-agent step, performed directly rather than through the Composio toolkit call in search_provider.py.
  • 6 apps stayed unknown — Pumble, fanbasis, Waterfall.io, Paygent Connect, iPayX, Consensus — either no official docs could be located, or the only source was an unofficial mirror. That's logged as the finding, not papered over.
  • Every has_mcp claim on well-known apps was re-checked live, because MCP rollout is the single fastest-moving fact in this dataset — and where pass 1 was wrong most often.

05

Run it yourself

Source repo structure and the two commands that reproduce this page's data.

Repo layout

data/apps_seed.json        the 100 apps
src/schema.py               shared record schema
src/search_provider.py      Composio-backed + stub search
src/research_agent.py       pass 1: search → extract → record
src/verify_agent.py         critic pass + human-check merge
src/pipeline.py             orchestrates the full run
src/report.py               master_dataset.json → patterns.json
gen_dataset.py               this submission's actual dataset build
output/                     pass1, verification, master, patterns

Reproduce

pip install -r requirements.txt
cp .env.example .env   # COMPOSIO_API_KEY, ANTHROPIC_API_KEY

# full pipeline against real Composio/Anthropic APIs
python -m src.pipeline --provider composio --verify-sample-size 18
python -m src.report

# this submission's dataset (no network/API keys needed —
# encodes the actual research + live verification performed)
python gen_dataset.py
